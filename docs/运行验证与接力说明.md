## 常用命令

在项目根目录执行：

```powershell
.\scripts\dev\setup-infra.ps1 -AllowOutsideProjectJunction
.\scripts\dev\start-demo.ps1
.\scripts\dev\status-infra.ps1
.\scripts\dev\verify-demo.ps1
.\scripts\dev\stop-demo.ps1
```

`setup-infra.ps1` 只负责准备便携工具。演示运行包内已经带好下载文件，不需要再次联网。

目录含中文或空格时，脚本会使用：

```text
D:\sky-take-out-demo -> 当前项目目录
```

这是给 MySQL 等原生 Windows 程序使用的 ASCII 目录联接，不复制源码，也不是第二个项目。

## 下一阶段任务

### B：分类与菜品

第一步，先按 `docs/api.md` 补齐分类和菜品 DTO、VO、Controller、Service、Mapper，完成 `/admin/category/**` 与 `/admin/dish/**`。第二步，实现 B 端分类页和菜品页。第三步，接入 `/user/dish/list`，在 H5 首页完成分类切换和菜品列表。最后新增菜品时调用公共上传接口。

### C：套餐

先完成套餐 CRUD、套餐菜品关联、上下架和 C 端套餐查询。然后开发 B 端套餐管理页，选择菜品时直接复用 B 已完成的菜品分页接口。H5 首页按当前分类展示套餐。

### D：订单

先实现订单提交、用户订单列表与详情、商家接单、派送和完成。重点先写清订单状态流转：

```text
1 待接单 -> 2 已接单 -> 3 派送中 -> 4 已完成
1 待接单 -> 5 已取消
```

后端接口稳定后，再开发 B 端订单页和 H5 确认订单、订单列表、订单详情。

### E：购物车、地址、报表和总协调

先完成购物车和地址簿，因为 D 的提交订单依赖这两块。再实现营业额、订单统计和销量 TOP10。最后统一核对 `docs/api.md`、`sql/init.sql` 和 Knife4j，组织全链路联调、Bug 台账和最终打包。

## 协作步骤

1. 从 `dev` 拉代码，不直接在 `dev` 上开发。
2. 每名成员创建 `feature/模块名` 分支。
3. 先改接口文档和数据库脚本，再写业务代码。
4. 单人闭环完成后再提交 PR。
5. 合并前至少跑一次 `.\scripts\dev\verify-demo.ps1`。
6. 接口有变化时，必须在群内通知，不能只改前端或只改后端。

## 接手检查

拿到源码包后按顺序检查：

1. JDK 是否为 17。
2. Node.js 是否为 20 或更高版本。
3. Maven 是否可用。
4. 是否能运行 `npm run build`。
5. 是否能运行 `mvn test`。
6. 启动基础设施后，`verify-demo.ps1` 是否全部显示 `PASS`。

出现 `PORT_IN_USE` 时，不要强停未知进程。先修改演示端口，并同步修改：

- `scripts/dev/run-backend.ps1`
- `scripts/dev/run-admin.ps1`
- `scripts/dev/run-h5.ps1`
- `scripts/dev/start-infra.ps1`
- `scripts/dev/status-infra.ps1`
- `scripts/dev/verify-demo.ps1`

## 打包说明

交接包分两种：

- 源码包：给下一位开发同学，包含代码、文档、SQL、测试和运行脚本。
- 演示包：包含源码、后端 JAR、前端构建产物和便携基础设施下载文件，适合没有 Docker 的电脑。

运行数据、数据库文件、MinIO 对象、账号数据、`node_modules` 和构建缓存不会放入交接包。
